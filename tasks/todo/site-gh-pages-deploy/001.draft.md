# Investigate GitHub Pages deployment for the project site

Depends on [[spa-site]]. Once the SPA exists, figure out what this repository
needs to serve it on GitHub Pages.

Questions to answer:
- Pages source: deploy from a branch (e.g. gh-pages) or via GitHub Actions
  (actions/deploy-pages)? Recommend one.
- Build + publish workflow steps and required `permissions` / `environment`.
- Project-page base path: assets and SPA client-side routing must work under the
  repo subpath (or a custom domain / CNAME if used).
- Interaction with existing workflows: the action stays thin and fast; the Pages
  pipeline must be separate and not affect e2e or the action itself.

Deliverable: a recommendation for how to deploy, with the concrete workflow
outline, ready to turn into an implementation task.
