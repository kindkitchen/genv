# genv-js: source-of-truth JS port of the merge pipeline

Why: define the merge semantics once, in JS, then (a) test the raw bash action
against it for parity and (b) reuse it in the SPA playground so the site becomes
trivial.

API: `genv(inputs) => string`. `inputs` mirror action.yml (snake_case), same
defaults:
- vars_obj, secrets_obj: key->value (object or JSON string)
- dotenv_content: ""
- vars_include_pattern ".*", vars_exclude_pattern <impossible sentinel>
- secrets_include_pattern ".*", secrets_exclude_pattern <impossible sentinel>
- content_from_vars_include_pattern "", content_from_secrets_include_pattern ""
(dotenv_path is irrelevant to content — the engine returns the file body.)

5-step append pipeline (order = priority; all conflicting keys kept, last-win on
consume):
1. content_from_vars (if pattern != ""): append raw value of each var key
   matching the pattern.
2. vars kv: for each var key matching include AND NOT exclude, append
   `KEY=<JSON.stringify(value)>`.
3. content_from_secrets (if pattern != ""): like 1 over secrets.
4. secrets kv: like 2 over secrets. (secrets outrank vars — appended later.)
5. dotenv_content: literal block appended last.

Bash-fidelity contract (must match action.yml byte output):
- regex match = jq test() (Oniguruma) vs JS RegExp — document the dialect caveat;
  fine for README patterns (`^CONFIG$`, `^TEST`, `GITHUB`, `.*`).
- value encoding `@json` ~= JSON.stringify (strings get quotes).
- every jq/echo step is newline-terminated; step 5 `echo "$DOTENV_CONTENT"`
  appends a trailing newline even when empty — replicate.
- object key order preserved (to_entries / insertion order).
- disabled content steps (pattern "") append nothing.
