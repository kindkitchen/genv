# Agnostic engine implemented, green, zero-dependency

Rewrote `engine/` to the four-layer pipeline from [[005.decision]] / [[006.decision]],
replacing the action.yml port.

Modules:
- `env-file.ts` — `parse` (text -> object: comments/blank skipped, `export`
  prefix, double-quote unescape, single-quote literal) and `stringify` (quotes
  values with whitespace/specials/empty; escapes `\ " \n \r \t`). They round-trip,
  so a nested-content value survives stringify -> parse.
- `merge.ts` (core, pure) — `Content` marker + `content()` + `is_content()`;
  `merge(sources)` folds ordered sources last-win, inlining content values via
  `parse`. Keys keep first-seen position. No patterns, no I/O.
- `filter.ts` (engine, non-core) — `filter(obj, {include,exclude,content})`,
  string|RegExp patterns; exclude overrides include; content tags matched keys.
- `genv.ts` — `merge_sources(sources)` (-> object) and `genv(sources)` (-> text)
  over `SourceInput = { data: string|object, include?, exclude?, content? }`.
- `mod.ts` — re-exports all layers. CLI has two entries: running the module
  directly pipes raw stdin as one env-file source (`cat .env | deno run -A
  mod.ts`); the exported `genv_cli` reads a JSON array of sources from stdin.

Tests (30, all green via `deno task test`): per-layer spec files
(`env-file`/`merge`/`filter`/`genv`.test.ts) + `e2e.test.ts` (spawns the pipe
entry via `deno run mod.ts` and `genv_cli` via `deno eval`). `deno task test`
passes `--allow-run=deno` for the e2e. `deno lint` + `deno fmt --check` clean.

Zero-dependency: dropped the `@std/assert` dev dep for a tiny local `assert.ts`
(`assert`, `assert_equals` with structural deep-equal); `deno.lock` now locks
nothing. README rewritten, CHANGELOG created.

Decisions realized: merge collapses to a resolved object (no duplicate lines);
content-vs-literal is structural (the `Content` marker), set by the filter layer's
`content` pattern, expanded by core. Public API fully replaces the old
`genv(inputs)`.

Remaining (now other tasks): the GitHub adapter mapping action inputs onto
SourceInput (action-js-parity); JSR publish (release); spa-site imports it.
