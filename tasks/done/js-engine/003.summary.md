# genv-js v0.1 implemented and green

Landed the engine as a Deno/JSR TS library (decision [[002.decision]]),
reproducing action.yml's 5-step pipeline per the fidelity contract in
[[001.draft]].

Files:
- `deno.json` — name `@kindkitchen/genv`, version 0.1.0, exports
  `./engine/mod.ts`, tasks `test`/`gen`, `@std/assert` import map.
- `engine/genv.ts` — `genv(inputs) => string` + `GenvInputs` type. Helpers:
  `as_object` (object-or-JSON-string), `raw_value` (jq -r rendering),
  `content_lines` (steps 1/3), `kv_lines` (steps 2/4). Defaults match action.yml
  (include `.*`, exclude sentinel, content patterns "" = disabled). Step 5 always
  appends `dotenv_content + "\n"`, so all-default output is `"\n"`.
- `engine/mod.ts` — re-exports + `import.meta.main` CLI (stdin JSON -> stdout
  dotenv).
- `engine/genv.test.ts` — 10 Deno.test cases (defaults, kv, JSON-string input,
  include/exclude, content_from_*, vars-then-secrets last-win, @json encoding,
  dotenv_content last, full pipeline).

Verified: `deno test` 10/10, `deno lint` clean, `deno fmt --check` clean, CLI
round-trip works.

Fidelity caveats (documented, not yet parity-proven): Oniguruma vs JS RegExp
dialect; jq `@json` vs `JSON.stringify` (match for common JSON); object key order
(JS reorders integer-like keys — irrelevant for env names).

Next: prove parity against the bash action (task action-js-parity); publish to
JSR when ready; spa-site then imports it. Possible follow-ups: more edge-case
tests, decide if engine should expose per-step breakdown for the playground's
illustrative view.
