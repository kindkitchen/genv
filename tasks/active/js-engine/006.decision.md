# Filtering (include/exclude/match) is an engine layer, not core

Refines [[005.decision]]. The include/exclude/match logic stays in the engine but
out of core. It is a separate JS-only layer placed exactly after parse (env-file
text -> object) and before merge — a per-source transform on the parsed object.

Pipeline layering:
1. util `parse`: env-file text -> object.
2. engine (non-core) filter layer: include/exclude/match applied per source on
   its object, before it enters the merge.
3. core: ordered last-win merge (+ nested-content expansion). Stays pure — no
   patterns, no filtering.
4. util `stringify`: object -> env-file text.

Effect: core knows only how to merge; pattern logic is reusable and testable on
its own; the GitHub adapter (action-js-parity) wires its *_include/_exclude/
content_from inputs to this filter layer rather than into core.
