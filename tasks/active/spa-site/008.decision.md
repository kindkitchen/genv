# Playground demonstrates the GitHub Action inputs (not the raw engine)

User chose: the playground exposes the action's inputs (vars_obj / secrets_obj /
dotenv_content + the 6 include/exclude/content_from patterns) — what users put in
their workflow yaml — rather than the engine's generic ordered-sources model.

A small in-site `from_action` (mirroring parity/adapter.ts) maps the inputs to the
engine's `SourceInput[]`; the published engine does the merge. Engine is loaded
in-browser from esm.sh (`https://esm.sh/jsr/@kindkitchen/genv@0.1.0`) — keeps the
no-build single-file decision ([[003.decision]]).

Consequence: the shown output is the engine's RESOLVED env (deduped, last-win,
values normalized by `stringify`), not the action's literal byte file (which keeps
duplicates/quotes). This matches the engine-as-source-of-truth framing and is
clearer for teaching last-win; the UI says so. Comments in dotenv_content are
dropped (the engine parses content sources).
