# Merge pipeline spec (from action.yml) the playground must reproduce

The action appends to the dotenv file in 5 ordered steps. Conflicting keys are
all kept; resolution relies on the consumer's "last written wins". The playground
must render the full appended file in order and illustratively mark lines
shadowed by a later same-key line.

Inputs: vars_obj, secrets_obj (key->value JSON), dotenv_content (literal), plus 6
regex patterns. Pattern matching uses jq `test()` (Oniguruma regex); value
encoding is `@json` (== JSON.stringify of the value).

Steps, each appending lines in this order:
1. content_from_vars: if content_from_vars_include_pattern != "" — for each var
   key matching it, append the raw value (multi-line dotenv content).
2. vars kv: for each var key matching vars_include_pattern AND NOT matching
   vars_exclude_pattern — append `KEY=<json-encoded value>`.
3. content_from_secrets: like step 1 over secrets, gated on
   content_from_secrets_include_pattern != "".
4. secrets kv: like step 2 over secrets, with secrets_include/exclude.
5. dotenv_content: literal block appended at the very bottom (absolute priority).

Defaults: include ".*"; exclude an impossible sentinel
(`NOTING_this_is_hardcoded_impossible_pattern{10}`) i.e. exclude nothing; content
patterns "" (step disabled). secrets_obj outranks vars_obj because appended later.

JS reimplementation is faithful and dependency-free: iterate entries in insertion
order, `new RegExp(pattern).test(key)`, JSON.stringify values. Fidelity caveat:
Oniguruma vs JS regex dialect differences — fine for README's common patterns
(`^CONFIG$`, `^TEST`, `GITHUB`, `.*`).
