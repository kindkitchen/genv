# Default site for the action: landing + docs + interactive playground

Update the repository with a SPA that serves as the default site of this GitHub
Action. Three concerns in one site:

1. Landing — purpose, key points (mirror README's "main key points": minimal
   coupling between repo vars/secrets and action files; flexible declaration
   strategy via include/exclude, content-vs-value, mapping, merge order).
2. Documentation — all inputs and their relations, the 5-step merge order, and
   the last-win hierarchy.
3. Interactive / illustrative playground — user supplies vars_obj, secrets_obj,
   the include/exclude/content patterns and dotenv_content, and sees the
   resulting .env produced live, illustrating how sources merge hierarchically
   and last-win resolves conflicts.

Goal: let a visitor try and feel the project without setting up a workflow.

Constraints to weigh (not yet decided): keep it as thin as the project ethos;
the real merge logic is bash + jq in action.yml — the playground needs an
equivalent client-side implementation that stays faithful to it.
