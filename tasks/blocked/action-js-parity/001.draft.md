# Parity: bash action validated against genv-js

Once genv-js lands as `genv(inputs) -> string`, build a parity harness:
- fixture corpus covering each option and the merge order (include/exclude,
  content-vs-kv, vars vs secrets priority, dotenv_content, empty/edge cases).
- run each fixture through both the real bash pipeline (action.yml steps / jq) and
  genv(); assert byte-equal output.
- wire into CI alongside the existing e2e.* actions, kept thin/fast (bash-driven).

Known fidelity risks to assert or document: Oniguruma vs JS regex dialect; jq
@json vs JSON.stringify; trailing-newline behavior of the empty dotenv_content
step. Each divergence is either a bash bug to fix or an engine caveat to record.
