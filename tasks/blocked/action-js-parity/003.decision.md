# Semantic parity; adapter + harness live in parent `parity/`

Two choices settled before building.

Parity basis = SEMANTIC, not byte (user-confirmed). The engine dropped byte
fidelity ([[js-engine/005.decision]]): bash emits duplicate lines and `@json`
quoting; the engine resolves to a deduped object. So both sides are run through
the engine `parse` and the resulting envs deep-equaled. Byte-exact was rejected —
it would mean re-introducing an action-faithful renderer the engine deliberately
shed.

Placement: the adapter is GitHub-aware, so it stays out of the agnostic engine.
It lives in the parent repo at `parity/`, importing `../engine/mod.ts`. Not
published, not part of the engine package.

The harness runs the REAL `action.yml`, not a copy: it parses action.yml
(`@std/yaml`, a dev-only parent dep — fine, not the shipped engine), resolves
`${{ inputs.* }}` in each step env, honours the step `if`, and executes the
bash/jq `run` blocks against a temp file. This keeps parity honest against the
actual action and guards adapter drift.
