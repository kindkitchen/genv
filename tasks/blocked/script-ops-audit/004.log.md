# Fixed two failing cumulative e2e jobs

First CI run failed two jobs: `content_from_vars` and `content_conflict`. Root
cause: step 2/4 (key=value) run UNCONDITIONALLY with the default
`*_include_pattern: ".*"`, so the content-blob keys were also dumped as
`KEY="...\n..."` lines, polluting the expected output. My earlier local check
was unfaithful — it skipped the unconditional kv steps.

Fix: in those two jobs, mark the content sources as content-only by excluding
them from the kv steps — `vars_exclude_pattern: ".*"` (and
`secrets_exclude_pattern: ".*"` for the conflict job). This is also the
realistic config a user needs to get content-only behavior under v1.0.0.

Built a faithful full-pipeline simulator (all 5 steps + real defaults),
confirmed it reproduces the 4 CI-green jobs exactly, then confirmed both fixes
PASS. The other 4 jobs untouched.

Lesson: when reusing old scenario inputs against the current action, the
unconditional kv steps + `.*` include defaults change the output vs the older
action versions those scenarios were written for. Still blocked on the re-run.
