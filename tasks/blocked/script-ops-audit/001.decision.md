# Audit findings and user verdicts

Audited all technical script operations: action.yml (composite bash/jq),
JUSTFILE (version/bump), e2e.* workflows.

Verified working: action.yml pipeline reproduced byte-for-byte locally
(escaping via jq `@json`, multiline content, empty defaults, impossible-exclude
default). JUSTFILE `just v` and `bump` correct.

Three issues raised; user verdicts:
1. e2e tests target the PUBLISHED tag (`uses: kindkitchen/genv@vX.Y.Z`), not
   local code, and each version's e2e only covered its newest feature. DECISION:
   make each next version's e2e cumulative — include all prior still-valid
   scenarios. Implemented in [[002.log]].
2. dotenv file never truncated (`>>` everywhere) -> duplicate keys on re-run.
   DECISION: won't fix. Last-win is the package's documented, intended hierarchy
   (merge many sources, last value wins). Fixing adds complexity, gains nothing.
3. Step 5 appends dotenv_content unconditionally -> trailing blank line on empty
   default. DECISION: won't fix, non-issue (command substitution strips it in
   asserts anyway).

Note: kept the structural choice of one-job-per-scenario and keeping all
existing per-version e2e files (each stays a smoke test of its own tag).
