# Made e2e v1.0.0 the cumulative suite

Rewrote `.github/workflows/e2e.self-invocation.v1.0.0.yml`: the single `deploy`
job became six jobs, one per still-valid historical scenario, all invoking
`kindkitchen/genv@v1.0.0`. Each job runs on a fresh runner so default ./.env is
clean — no per-path isolation needed. Trigger unchanged (push tag v1.0.0 +
main). Added `permissions: {}` (action only writes the runner workspace; the old
id-token/contents:write grants were unnecessary).

Jobs and their origin version:
- dotenv_content (v0.0.11)
- content_from_vars (v0.1.0)
- content_conflict — conflicting HELLO key, last-win (v0.1.1)
- vars_filter — content_from_vars + include/exclude (v0.1.2)
- secrets_filter — vars kv + secrets content + secrets filters (v0.1.4)
- all_combined — every option at once (v1.0.0)

All six scenarios were reproduced locally against the current action.yml
pipeline and passed before encoding. YAML validated (parses, 6 jobs, triggers
intact). Older per-version e2e files left untouched.

Convention going forward: a new version copies this file, bumps the `@vX.Y.Z`
refs and trigger, and adds one job for the behavior it introduces.

Not run on real CI yet (no push per project rules / user controls release).
